# Chapter 30: Implementation of IoT with Raspberry Pi — Part I: Sensing & Sockets

## Core Concept
This chapter explores end-to-end IoT implementation on the Raspberry Pi: acquiring physical environmental data through sensor interfacing, serializing readings, and transmitting live telemetry packets over local networks to remote servers using Python network sockets.

---

## 1. Interfacing Environmental Sensors with Raspberry Pi
* **Reading Digital Pins:** Connecting digital sensors (such as PIR motion sensors or ultrasonic HC-SR04) to GPIO pins:
  * For ultrasonic sensors, the 5V Echo pulse must be stepped down to 3.3V using a **two-resistor voltage divider** before entering a Pi input pin.
* **Polling Loop:** Python scripts run continuous background loops polling sensor states and logging timestamps.

---

## 2. Network Communication: Python Socket Programming
Network sockets allow Python programs to establish bidirectional network connections across local networks and the internet.

### UDP Sockets (User Datagram Protocol)
* **Characteristics:** Connectionless, lightweight, low-latency transport without connection handshakes, acknowledgements, or flow control.
* **Fit for IoT:** Ideal for high-frequency sensor streams where the loss of an occasional reading is acceptable in exchange for minimal network overhead and speed.
* **Implementation Flow:**
  * **Client (Pi Transmitter):**
    1. Creates socket: `s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)`
    2. Encodes sensor payload to bytes: `data = str(sensor_val).encode('utf-8')`
    3. Transmits packet: `s.sendto(data, (SERVER_IP, SERVER_PORT))`
  * **Server (Receiver):**
    1. Creates datagram socket and binds to local address: `s.bind((HOST, PORT))`
    2. Listens for incoming data: `data, addr = s.recvfrom(1024)`

---

## 3. Data Processing and Telemetry Flow
* **Edge Preprocessing:** The Raspberry Pi can locally compute running averages, detect threshold breaches, and filter noise before transmitting packets to backend servers.
* **Network Payload Serialization:** Sensor readings are bundled with device identifiers and epoch timestamps before socket dispatch.

---

## Key Exam Takeaways
* **Socket Family:** `socket.AF_INET` specifies IPv4 network addressing.
* **Socket Type for UDP:** `socket.SOCK_DGRAM` designates datagram/UDP transmission.
* **UDP Fit:** Chosen for low overhead and minimal latency in real-time sensor streams.
* **Voltage Step-Down:** A voltage divider is mandatory when connecting 5V sensor outputs (like HC-SR04 Echo) to 3.3V Pi GPIO pins.
* **Data Encoding:** Python 3 strings must be converted to raw bytes (`.encode()`) before transmission over sockets.
