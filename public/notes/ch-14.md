# Chapter 14: Sensor Networks — Part I: Architecture & Topologies

## Core Concept
A Wireless Sensor Network (WSN) is a distributed collection of autonomous, resource-constrained sensor nodes collaborating to monitor physical or environmental conditions. Data is collected across vast geographic terrains and routed through multi-hop paths to one or more central collection points called Sink Nodes or Base Stations.

---

## 1. Internal Architecture of a Sensor Node
Each individual sensor node contains four core hardware subsystems:
1. **Sensing Subsystem:** Contains sensors and Analog-to-Digital Converters (ADCs) to sample physical phenomena.
2. **Processing Subsystem:** Microcontroller (MCU) and memory to execute local algorithms and buffer packet queues.
3. **Communication Subsystem:** Low-power RF transceiver to transmit and receive radio packets.
4. **Power Subsystem:** Battery and optional energy-harvesting modules (such as mini solar cells).

---

## 2. Multi-Hop Communication and Sink Nodes
* **Single-Hop vs. Multi-Hop:** Sensor nodes have limited radio transmission power to conserve battery. Transmitting long distances directly to a base station drains energy quickly. Instead, nodes use multi-hop routing, relaying packets through neighboring intermediate nodes.
* **Sink Node (Base Station):** A high-resource gateway node connected to main power. It aggregates data arriving from the entire mesh and forwards it to cloud servers or monitoring centers.

---

## 3. Network Topologies in WSN
* **Star Topology:** Nodes communicate directly with a single central sink. Simple and low latency, but limited in physical coverage range and vulnerable to a single point of failure.
* **Tree / Cluster Topology:** Nodes group into clusters led by **Cluster Heads (CH)**. Cluster Heads aggregate data from local member sensors, remove redundant readings, and route the compressed summary up the hierarchy to the sink.
* **Mesh Topology:** Redundant multi-hop links between peer nodes. Provides self-configuring deployment, load balancing, and self-healing paths around failed nodes.

---

## 4. Fundamental Design Constraints in WSN
* **Severe Energy Limitations:** Batteries are often non-rechargeable and deployed in inaccessible environments (forests, ocean buoys, structural foundations).
* **Bandwidth & Processing Limitations:** Radios provide low data rates, and microcontrollers have only a few kilobytes of RAM.
* **Data-Centric Addressing:** WSNs query for data rather than device identity (for example, "report all locations where temperature exceeds 40 degrees" rather than addressing specific node IPs).

---

## Key Exam Takeaways
* **Core Hardware Units:** Sensing, Processing, Communication, and Power.
* **Multi-Hop Rationale:** Drastically lowers transmission power consumption and extends geographic coverage.
* **Sink Node Role:** Data aggregation gateway bridging the sensor mesh to external internet systems.
* **Cluster Head Benefit:** Aggregates and compresses local readings, reducing redundant radio traffic.
* **Addressing Nature:** Primarily data-centric rather than traditional host-centric IP routing.
