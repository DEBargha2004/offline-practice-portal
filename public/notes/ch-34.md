# Chapter 34: Software Defined Networking (SDN) — Part II: Controllers & Placement

## Core Concept
In an SDN architecture, the network's reliability, latency, and throughput depend heavily on how controllers are deployed. This chapter explores the Controller Placement Problem, multi-controller deployment models, and the standardized APIs governing control plane communications.

---

## 1. The Controller Placement Problem (CPP)
* **Definition:** The optimization challenge of determining the minimum number of SDN controllers required and where to physically locate them within a network topology.
* **Optimization Goals:**
  * Minimize control latency between switches and controllers.
  * Balance load across multiple active controllers.
  * Ensure fault tolerance: if one controller crashes, surviving controllers seamlessly absorb the orphaned switches.

---

## 2. SDN API Taxonomy
* **Southbound API:** Connects the Control Plane down to the Data Plane (e.g., **OpenFlow**, NETCONF). Allows controllers to program switch flow tables.
* **Northbound API:** Connects the Control Plane up to the Application Plane (typically RESTful APIs). Allows business applications to request network bandwidth, create virtual paths, or apply security rules.
* **East-Westbound API:** Facilitates synchronization and state-sharing **between multiple SDN controllers** in a distributed cluster.

---

## 3. Controller Deployment Architectures
* **Flat Architecture:**
  * Multiple peer controllers operate at the same hierarchical tier.
  * Each controller manages a specific network partition and synchronizes global state using East-West APIs.
  * Eliminates a single point of failure but introduces state synchronization overhead.
* **Hierarchical Architecture:**
  * Local controllers manage localized, high-speed subnets directly.
  * A master root controller oversees all local controllers, resolving global routing and inter-domain path policies.
  * Scales exceptionally well across large, geographically distributed networks.
* **Mesh Architecture:**
  * Controllers are redundantly interconnected with multiple cross-links. Switches can establish connections to multiple candidate controllers for instant failover.

---

## Key Exam Takeaways
* **Southbound API Function:** Manages communication between controller and switch (e.g., OpenFlow).
* **Northbound API Function:** Exposes programmable network control to high-level applications via REST APIs.
* **East-Westbound API Function:** Coordinates state and synchronizes topology across multiple controllers.
* **Controller Placement Problem Objective:** Optimizes controller location to minimize propagation latency and maximize fault tolerance.
* **Hierarchical Model Benefit:** Combines rapid local response with centralized global orchestration.
